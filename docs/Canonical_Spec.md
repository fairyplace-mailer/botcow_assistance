Ниже — **каноническое оглавление полного ТЗ** для кодера, который пишет бота на **OpenAI Responses API**. Такая структура покрывает ключевые реальные сущности стека: conversation state, streaming, tools/function calling, structured outputs, file inputs, background mode, webhooks и управление контекстом.

Ты SHALL описать существующий в fairyplace-mailer/botcow_assistance в ветке provecta код ТОЧНО в соответствии с этим **каноническим оглавление полного ТЗ**
Ты SHALL NOT фантазировать, предполагать или домысливать.
Описываешь только то, что есть в реальности.
Пункты, в которые нечего вписать заполняешь фразами типа "эти данные в коде отсутствуют (не отражены, не проработаны)", или типа того.
Результат работы оформляешь в файл docs/exist_spec.md в ветке provecta.
