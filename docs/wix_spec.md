# Wix_spec.md

## ТЕХНИЧЕСКОЕ ЗАДАНИЕ  
**Проект:** Автономный dev-ассистент (OpenAI + GitHub + Vercel)  
**Хостинг:** Vercel Hobby  
**Стек:** TypeScript, Vercel Serverless Functions, Prisma, Postgres, Vercel Blob

---

## 1. Цель
Создать и поддерживать **актуальный RAG-банк знаний** по **всем страницам**  
`https://dev.wix.com/docs/*` (≈150–200 страниц) для:
- ответов клиенту,
- генерации и анализа кода.

---

## 2. Принципы
- Используется **только RAG**.
- Fine-tuning **не применяется**.
- Вся фактическая информация берётся из локального индекса (embeddings).
- Старые / удалённые страницы **полностью удаляются** (Postgres + Blob).

---

## 3. Кроулинг Wix Docs
- Тип: **контролируемый fetcher**, не spider.
- Охват: все страницы `dev.wix.com/docs/*`.
- Частота: **1 раз в сутки**.
- Выполнение: батчами (5–10 страниц за запуск).

### Процесс обновления страницы
1. Fetch HTML.
2. Приведение к Markdown.
3. Расчёт hash контента.
4. Если hash изменился:
   - пересборка чанков,
   - пересчёт embeddings,
   - перезапись данных.
5. Если страница недоступна:
   - удалить document, chunks и blob-файл.

---

## 4. Хранение данных

### Postgres (через Prisma)
Минимальные таблицы:
- `documents` — url, hash, updated_at  
- `chunks` — text, embedding, document_id  
- `crawl_jobs` — состояние обновлений  
- `github_cache` — кэш GitHub-запросов  

### Vercel Blob
- Хранить только markdown-контент страниц.
- Не хранить HTML, версии и дубликаты.
- Blob не используется для поиска.

---

## 5. RAG
- Размер чанков: 500–1000 токенов.
- Embeddings: OpenAI, батчами.
- При ответе бота:
  1. Semantic search (top-K 5–8).
  2. Подстановка чанков в prompt.
  3. Генерация ответа или кода.

---

## 6. GitHub Search
**Проблема:** лимиты поиска внутри репозиториев одного GitHub-аккаунта.

**Решение:**
- Использовать GitHub **GraphQL API**.
- Один централизованный search-service.
- Обязательно:
  - кэширование запросов (Postgres),
  - дедупликация,
  - rate-limit guard,
  - backoff + retry.

**Порядок поиска:**
1. Проверка локального кэша.
2. GitHub API (только при необходимости).

---

## 7. Cron и обслуживание
- Cron Job: **1 раз в сутки**, **02:00 UTC**.
- Окно выполнения: ≥ 60 минут (Vercel Hobby).
- Выполняет:
  - обновление Wix Docs,
  - удаление orphan-данных,
  - контроль роста Blob.

Все операции должны быть **идемпотентными**.

---

## 8. Ограничения
- Только возможности **Vercel Hobby**.
- Без background workers.
- Без long-running задач.
- Все процессы через serverless + cron.
